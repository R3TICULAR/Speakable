# SEO Heading Strategy for Documentation Pages

When writing or editing documentation pages, follow this heading structure for search engine optimization:

## H1 (One per page)

- Feature the primary target keyword prominently
- Clearly state the page's purpose
- Keep the H1 and the page's `<title>` tag very similar
- Make it clickable and descriptive (not generic like "Guide" or "Overview")
- Place within the first visible content block

## H2s (Multiple per page, "chapters")

- Act as the primary sections of the page
- Include secondary keywords and related search phrases
- Help both search engines and users skim the content quickly
- Each H2 should cover a distinct subtopic

## H3s and below (Subsections within H2s)

- Break down H2 topics into digestible subtopics
- Use for step-by-step instructions, examples, or comparisons within a section

## Hierarchy Rules

- NEVER skip heading levels (H1 to H3 without an H2)
- Always nest sequentially: H1 > H2 > H3 > H4
- Think of it like a textbook: H1 is the title, H2s are chapters, H3s are subchapters
- Only one H1 per page

## Why This Matters

- **Search Intent**: Search engines scan heading tags to understand page topic and content relationships
- **User Experience**: Clear headings let users scan for the exact information they need
- **Accessibility**: Screen readers use heading structure for navigation (users jump between headings to browse content)
- **Featured Snippets**: Well-structured H2/H3 content is more likely to be pulled into Google featured snippets

## Applying to Speakable Docs

- The H1 should include the page's primary keyword (e.g., "Screen Reader Testing in CI/CD" not "CI Integration Guide")
- Place the primary keyword in the first 100 words of body content after the H1
- Use H2s to target secondary/long-tail keywords related to the page topic
- Include at least one H2 with a "how to" or question format for snippet eligibility
- Structure comparison sections as H2s (e.g., "VoiceOver vs NVDA" as an H2 under a comparison page)
